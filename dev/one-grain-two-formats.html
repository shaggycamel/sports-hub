One grain, two formats

Category and points leagues disagree about how a category is scored, not about what gets recorded. Store the observation once; let the format be a rule applied on the way out.

The pipeline

Why the wide table can't hold this

Each league scores its own subset. The wide table has to carry the union as fixed columns, so most cells are already empty — and a stat outside the union needs an ALTER TABLE.

Twenty columns, fifteen of them a fixed category vocabulary. Every new scored stat is a migration.

fty.matchup_box_score_long — after

  • season
  • platform
  • league_id
  • matchup
  • competitor_id
  • category
  • value
  • fantasy_points
  • result

Six key columns and one value. A new scored stat is a row. Nothing in the shape reveals which format the league runs.

fantasy_points and result came out because neither is an observation. The weight already lives in fty.league_categories.points, and the league's scoring items carry no pointsOverrides — checked live — so value × points is exact. A category result is a comparison, which doesn't exist until an opponent is in the query.

The same rows, read two ways

One competitor's category rows for a single matchup. The left reading needs an opponent and a direction; the right reading needs a weight. Neither needs a column of its own.
